# Local domain foundation (T06)

Seven SQL migrations create 27 Prisma models, including the proof-event/heartbeat tables. Tenant-owned relations use compound store/workspace keys. Workspace → one shop and one selected Meta account is database constrained. External identifiers are strings. Times use `timestamptz`, preserving instants; the account retains its provider timezone separately. Observed subtotal is `numeric(20,6)` and currency is a separate three-letter code. No float revenue arithmetic is implemented.

`StoreReservation.storeId` is the exclusive slot. Create an experiment as a draft, insert the reservation, then change it to publishing/running in a transaction. The status trigger locks and checks the reservation. Parallel reservation inserts for different experiments in one store cannot both succeed. Deleting/replacing a reservation while its experiment is running/publishing is rejected; `releaseAfter` also prevents early release. The T27 lifecycle service must set releaseAfter to the last assignment's seven-day maturity and implement pause/end/retry semantics. This schema does not claim that T27 is implemented.

Revisions and variant content reject update/delete through triggers. Assignments reject updates, preserving visitor variant/entry-ad identity; privacy deletion remains possible. Snapshot JSON is the intended immutable canonical revision content; T07/T24 must validate schema/copy/weights and create all child variants transactionally. Normal application services have no mutable revision API. Retention/privacy work must deliberately handle immutable content records and linked-row deletion order.

Uniqueness: assignment `(storeId,experimentId,visitorId)`; ingested event `(storeId,source,providerEventId)` where custom source uses the app's stable ID; proof event ID includes store, kind and logical app/Shopify event ID. Identity lookup indexes include store, Shopify client and time. All cross-store assignment/variant/purchase references use compound foreign keys.

Purchase aliases reserve `(storeId, kind, providerId)` for `order` or `checkout`. T28 must transactionally resolve aliases and attach a late order alias to the existing purchase; conflicting aliases must quarantine/merge under an explicit tested policy. Alias constraints and decimal storage are tested now; production alias reconciliation is not yet implemented. Raw proof checkouts carry no amount: exact pixel revenue semantics are intentionally deferred to T28's pinned-field verification.

Prisma does not represent SQL check constraints/triggers in its schema language. Keep the SQL migrations authoritative and run `test:constraints` on future changes; do not use schema push or replace migrations with a generated diff that drops this protection. ORM-level access alone does not authorise merchant requests: T05's verified workspace membership is still required. The current app exposes no merchant CRUD APIs.

Verification uses a fresh random schema, executes every migration, then checks tenant mapping failures, no running state without reservation, racing inserts, reservation protection, immutable copy/assignment, one visitor cohort, decimal precision, checkout/order aliases and cross-store purchase rejection. It drops only its generated test schema on completion. The normal development seed creates a repeatable seed heartbeat; merchant seed data is deliberately absent.

T07 adds validating/ready experiment states. T08 makes outbox idempotency workspace scoped, adds safe failure codes and durable webhook receipts. T17 adds transactional ingestion-rate counters. The worker now processes only the allowlisted local audit effect; provider/domain lifecycle jobs remain pending.
